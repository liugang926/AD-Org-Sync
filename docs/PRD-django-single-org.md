# 单组织目录同步与钉钉自助密码重置 PRD

版本：v1.1 实施版（未投产全面重构）  
日期：2026-09-23  
技术方向：Django 单体应用  
产品范围：单组织、单通讯录来源、单 AD 域、钉钉自助重置密码

## 1. 产品目标与范围解释

将现有平台收敛为一个易配置、易使用、易维护的内部工具，完成两件事：

1. 将一个组织的部门和人员同步到 AD，并维护可靠的人员与账号关联。
2. 员工通过钉钉验证身份后，只能重置通过 LDAPS 实时唯一匹配的本人 AD 账号密码；不要求同步成功或已有本地绑定。

“只取现有平台的同步关联逻辑”解释为：新系统继承现有同步、账号匹配、绑定及必要保护规则，不迁移旧平台的管理体系、页面结构和通用扩展框架。钉钉密码重置继续作为原始核心目标保留。

本 PRD 是重构需求，不代表这些功能已经在 Django 中实现。现有实现依据第 13 节所列本地代码与文档；新增约束和行为调整均明确标注。

## 2. 产品边界

### 2.1 本期必须实现

- 固定一个组织、一套通讯录连接和一个 AD 连接。
- 部门层级读取、部门与 OU 关联、人员创建与属性更新。
- 已有 AD 账号匹配、人工绑定、绑定修正与排除同步。
- 全量、部门及指定人员同步；指定单人作为指定人员的特例。
- 同步预览、人工执行、定时执行、任务结果与异常定位。
- 完整全量同步下的离职禁用，以及批量禁用保护。
- 钉钉身份验证、自助密码重置、必要审计。

### 2.2 不纳入本期

- 多组织、多 AD 目标、多个通讯录来源同时同步。
- 通用连接器市场、HR 扩展框架、跨平台主身份和身份关系图谱。
- 身份治理、生命周期、数据质量、配置发布等独立管理中心。
- 可编程策略引擎、多级审批、通用 Webhook 和外部事件投递平台。
- 自动删除 AD 用户、自动删除 OU、自动合并账号。
- 群组层级治理、经理关系和邮箱别名专项治理；确有需求另行立项。
- 桌面端、EXE 打包、双语及基础/高级界面切换。
- Redis、Celery、微服务、独立缓存、私有镜像仓库和镜像加速体系。

### 2.3 默认假设与上线前需固化的配置

用户已确认首期通讯录来源为钉钉，仅交付钉钉适配器。

不建设跨平台员工关联。AD 根 OU、账号命名字段、离职处理方式和同步周期通过单一配置设置；已有绑定时不得直接更换管理范围。

## 3. 用户与核心流程

| 用户 | 可以执行的操作 |
| --- | --- |
| 管理员 | 配置连接、维护绑定、预览和执行同步、查看日志 |
| 员工 | 在钉钉中验证本人身份，查看自己的账号并重置密码 |

管理员首次配置流程：连接测试 → 获取通讯录 → 指定同步根部门与 AD 根 OU → 选择关联字段和命名方式 → 处理冲突 → 预览 → 执行。

日常流程：定时读取通讯录并同步；管理员只处理失败项、冲突项和超过禁用阈值的任务。

员工流程：打开钉钉应用 → 身份验证 → 展示本人账号 → 输入并确认新密码 → 提交 → 显示结果。

## 4. 同步与关联规则

### FR-01 读取来源与确定范围

- 必须读取配置范围内的全部部门及人员分页，记录开始时间、完成时间、数量和完整性。
- 连接测试应验证组织及人员读取，不能仅以取得令牌视为成功。
- 读取失败保留上次成功数据供查看，并标明更新时间；不得把旧数据当作本次成功采集。
- 任一分页或部门失败时，本次数据视为不完整，不得据此计算离职人员。
- 本期简化约束：不完整采集不得执行本次 AD 写入，任务显示可重试的失败原因。
- 全量指“已配置管理范围的完整读取”，不是整个企业或整个 AD 域。
- 部门范围包括其子部门；指定人员范围只处理被选人员。
- 缩小同步范围属于配置变更，不自动把移出范围的用户判为离职。

### FR-02 稳定身份与已有绑定

- 单组织内以钉钉 source_user_id 唯一标识人员；配置保存企业与 AD 目录身份锚点，身份改变后禁止复用原数据库绑定，不引入多租户字段体系。
- 工号、姓名、邮箱及生成的 AD 用户名不能作为来源身份主键。
- 匹配优先顺序：有效人工绑定 → 有效已有绑定 → 按已配置字段生成匹配候选 → 无候选时评估新建。
- 一个来源用户最多有一个有效 AD 绑定；一个 AD 账号最多绑定一个受管来源用户。
- 工号或姓名改变时，有效绑定保持原目标，不触发重新认领或重复创建。
- 已禁用绑定不得被自动规则重新启用。
- 新系统统一以 AD objectGUID 标识绑定目标，用户名和 DN 用于展示及定位辅助。这是新系统的统一要求；不迁移旧平台数据。
- 同名但 objectGUID 不同的 AD 账号视为不同对象，必须重新确认。

### FR-03 匹配已有 AD 账号

- 本期仅提供一套明确的匹配字段配置，不提供规则优先级编排器。
- 沿用保守自动匹配原则：工号类标识存在、来源内唯一、AD 精确命中一个、目标未被占用且不受保护时，才可提出自动绑定。
- 邮箱、用户名等其他字段匹配结果作为人工确认候选；姓名不用于自动绑定。
- 标识缺失、重复、多个 AD 候选、目标已绑定、受保护或目标身份无法确认时阻断该用户。
- 在职来源命中已禁用 AD 账号时，要求管理员确认；不得默认恢复账号。
- 匹配字段与新账号命名字段独立：找到人员和给新账号命名是两个不同步骤。
- 匹配候选不是实际绑定，预览不得修改有效绑定。

### FR-04 新建账号与命名

- 对无已有绑定、无 AD 命中、所需标识完整且唯一的用户提出新建计划。
- 首期命名仅提供：平台 userId、工号、邮箱前缀，选择其中一种；人工绑定优先。
- 保留现有规范化行为：处理不允许的字符、限制 sAMAccountName 长度、检测大小写不敏感的碰撞；预览显示原值与处理结果。
- 本期简化调整：空结果、重复或截断导致的碰撞一律转人工处理，不静默添加后缀创建账号。
- 新建账号必须位于受管 OU 内；初始化密码随机生成且不写日志、不展示固定公共密码。
- 新建账号的启用和首次改密策略在设置中明确，创建过程中未完成必要步骤的账号不得标为成功。

### FR-05 人工绑定与修正

- 管理员从真实来源人员和实际存在的 AD 账号中选择，提交前实时验证双方及目标保护状态。
- 禁止将一个目标重复绑定给不同人员。
- 修正绑定展示旧目标与新目标，填写原因，记录操作者和时间。
- 解绑只解除本地同步关联并排除自动重新认领，不删除或禁用 AD 账号；密码重置独立以实时 LDAPS 匹配为准。
- 来源用户暂时不在当前数据中时，保留绑定并显示异常，不自动清除。
- 目标查询失败与目标不存在必须区分；网络失败不能触发解绑或重建。
- 已确认目标不存在时由管理员解除绑定，再重新预览；不提供自动清扫绑定任务。

### FR-06 部门与 OU

- 维护 source_department_id 与 OU 的明确关联，不以部门名称作为唯一键。
- 默认在配置的根 OU 下对应来源层级创建 OU；允许管理员指定某部门对应的已有 OU。
- 多部门人员使用来源明确提供的主部门，管理员指定的部门优先。
- 简化调整：没有可确定的主部门时要求人工指定，不使用难以解释的自动兜底顺序。
- 人员部门变更时，可在预览中提出账号移动；仅允许在受管边界内执行。
- 来源部门改名或调整层级时显示差异，首期由管理员确认新的 OU 对应关系，不自动删除、移动或重命名整个 OU 子树。
- 不接管根 OU 以外的目录对象；人工绑定范围之外的账号必须先明确纳入受管范围。

### FR-07 属性更新与离职

- 只更新管理员启用的字段，首期限定为显示名、邮箱、电话、职位和部门等基础属性。
- 默认来源空值不清空 AD 值；需要清空的字段必须明确启用此行为。
- 属性同步不得覆盖密码；账号名变更首期不自动执行。
- 仅完整、成功的全量采集可以评估缺失用户的离职处理。
- 部门及指定人员同步不执行离职禁用、不执行全局状态清理、不更新全量成功标记。
- 只处理本系统已绑定并纳入管理的账号，不按 AD 全域差集禁用人员。
- 默认仅禁用，保留账号、绑定和审计；不自动删除。
- 禁用数量或比例超过配置阈值时，阻断整个写入任务并展示受影响清单；审批页面可简化为一次确认，保护不能去掉。
- 服务账号、共享账号、受保护账号和排除人员不参与常规自动同步。

### FR-08 预览、执行与结果

- 预览按人员列出新建、更新、移动、绑定、禁用、跳过、冲突及原因，并给出前后值。
- 页面区分四种事实：命名候选、当前保存的绑定、预览计划、实际执行结果。
- 手动执行使用明确的预览计划；范围、配置、来源数据或绑定变化后必须重新预览。
- 执行前复核目标身份及关键状态，目标已变化时阻断相关操作，不能依赖陈旧预览覆盖 AD。
- 同一时刻只执行一个同步任务；重复点击不得产生并发任务。
- 定时任务每次重新采集并生成计划；正常低风险计划可自动执行，冲突和高风险任务停止并等待处理。这是替代旧平台多层发布审批的简化行为。
- 任务状态：排队、运行、成功、部分失败、失败、因冲突阻断、需确认。
- AD 写入与本地数据库不具备共同事务，页面不得承诺全量回滚。
- 调整原有整批提交语义：每名人员 AD 操作成功后独立保存该人的绑定；后续人员失败不丢弃此前成功绑定。整批可标记部分失败，AD 写入成功但本地提交失败时保留执行证据，重试先核验。
- 重试必须重新核验已成功写入的 AD 对象，避免重复创建；如缺少可靠目标证据则转人工处理。
- 进程中断的运行任务标为中断失败；恢复时重建计划，不盲目重放旧写入。

## 5. 钉钉自助密码重置

### FR-09 员工验证与授权（最新用户要求）

- 员工入口与管理员会话分离，不要求员工拥有后台账号。
- 前端取得钉钉授权码，由服务端使用配置企业应用的凭据换取可信 userId 并读取员工详情；不信任前端提交的人员标识。
- 服务端按独立配置的匹配方式实时查询 LDAPS：钉钉工号 → AD employeeID、钉钉邮箱 → AD mail，或钉钉 userId → AD sAMAccountName。
- 此流程不得读取同步任务状态作为授权依据；没有同步记录、没有本地人员或绑定记录也可以使用。
- 唯一匹配到未禁用且不受保护的账号后，展示脱敏账号，由员工选择是否确认重置。
- 无匹配、多匹配、可信字段缺失、目标受保护或账号禁用时停止，员工不能手工输入其他 AD 账号绕过验证。
- 验证会话绑定钉钉 userId、AD objectGUID 和配置版本。提交时重新读取员工身份并查询 AD；匹配目标改变或配置改变须重新验证。

### FR-10 密码提交与结果

- 展示本人姓名和脱敏账号，填写新密码及确认密码。
- 服务端校验两次输入，并将 AD 密码策略校验结果作为最终依据。
- 通过 LDAPS 加密连接修改密码；按用户最新确认，自签证书不需要预先信任，默认不验证证书可信链及主机名，CA 文件不作为部署前提。保留 `LDAP_VERIFY_CERT=true` 可选严格校验；必须提供 HTTPS 员工入口。
- 默认不自动解锁；管理员可启用“重置成功后解锁”，解锁失败须独立反馈，不能伪报全部成功。
- 使用短期验证会话、CSRF 防护、按身份和来源地址限流；会话及令牌不以明文持久化。
- 成功后立即消费验证会话，重复提交不能再次执行重置。
- 审计记录员工标识、目标对象、时间、结果和脱敏原因；不记录密码、授权码或访问令牌。
- 超时导致结果不明时显示结果待确认，不自动重复提交密码，也不直接断言密码未修改。

## 6. 页面要求

| 页面 | 必需内容与操作 |
| --- | --- |
| 同步 | 连接状态、最近成功时间、下次执行时间、范围、预览、执行、失败项 |
| 人员与绑定 | 搜索分页、来源人员、AD 账号、关联状态、人工绑定、修正、排除、状态核验 |
| 设置 | 单一来源、AD、根部门和 OU、匹配字段、命名方式、属性字段、周期、禁用阈值、钉钉配置与独立密码重置匹配方式 |
| 日志 | 同步任务及逐项结果、绑定变更、密码重置审计，按时间和结果筛选 |
| 员工密码重置 | 移动端身份验证、本人账号、密码输入、结果及错误指引 |

管理页面中文优先。Django Admin 承担基础配置和只读审计，绑定写入必须经过业务校验；不得开放可绕过校验的通用模型编辑或批量修改动作。同步与员工重置使用专用模板页面。

## 7. 最小数据模型

以下是业务实体，不要求每项一张独立表；Django 自带管理员和会话表另计。

| 实体 | 核心内容 |
| --- | --- |
| 应用配置 | 固定企业标识、来源类型、连接引用、范围、周期、策略和配置版本 |
| 来源批次及人员/部门 | 采集版本、完整性、稳定标识、当前基础属性 |
| 部门关联 | 来源部门标识、AD OU 标识及 DN、人工指定标记 |
| 账号绑定 | 稳定钉钉 userId、AD objectGUID、用户名、状态、绑定方式和版本 |
| 同步任务及操作 | 触发方式、范围、计划摘要、版本指纹、目标证据和逐项结果 |
| 员工验证会话 | 钉钉 userId、实时匹配的 AD objectGUID、配置指纹、令牌摘要、有效期及消费状态 |
| 审计事件 | 操作者、对象、动作、时间、脱敏结果 |

只保留运行所需的当前数据及有限期任务证据；不建设历史快照浏览平台。凭据使用受限配置或加密存储，禁止管理页面回显明文密钥。

## 8. 技术与部署约束

- Django 单体、服务端模板、Django ORM 和 SQLite；不建设前后端分离工程。
- 服务分为 directory（来源与 AD）、sync（计划与执行）、sspr（验证与重置），避免搬入旧平台的服务容器和治理仓储体系。
- 一个 Web 进程加一个轻量任务执行进程，使用数据库任务表和执行锁；网页请求只提交任务。
- 定时任务由系统调度调用 Django 管理命令入队，与手动同步共用执行路径；不再同时维护另一套应用内调度器。
- 明确区分“一个应用”与“一个进程”；不可为追求单进程而让同步长任务阻塞员工密码重置。
- 部署只选一个宿主方式，优先延续当前生产宿主，不同时维护 Windows 服务和 Docker 两套发布流程。
- 无镜像缓存或代理服务；HTTPS 复用现有网关，没有网关时保留一个反向代理。
- 保留应用健康检查、数据库备份和上一版本应用；数据库升级后的回退须有对应数据恢复方案。
- 本 PRD 不指定 Django 具体版本，实施时选择仍受支持的版本并锁定依赖。

## 9. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 唯一工号匹配已有 AD 账号 | 预览提出绑定，执行后关联原账号，不创建第二个账号 |
| AC-02 | 人工绑定与命名候选不同 | 使用人工绑定目标，候选不覆盖绑定 |
| AC-03 | 工号改变或姓名改变 | 稳定 source_user_id 继续关联原 objectGUID |
| AC-04 | 工号重复、AD 多候选或目标已占用 | 阻断相关人员并展示明确原因，不任取一条 |
| AC-05 | 仅运行预览 | AD 及有效绑定均无变更 |
| AC-06 | 预览后修改范围或绑定 | 原计划失效，无法直接执行 |
| AC-07 | 新人员创建与重复执行 | 第一次创建成功，第二次不重复创建 |
| AC-08 | 人员换部门 | 仅按批准计划在受管 OU 内移动，保留对象身份 |
| AC-09 | 局部同步缺少其他人员 | 不禁用范围外账号，不更新全量成功标记 |
| AC-10 | 来源分页失败或返回异常空目录 | 不进行本次写入，不按缺失批量禁用 |
| AC-11 | 全量离职人数超过阈值 | 整体任务停止写入，展示需确认名单 |
| AC-12 | 部分写入成功后失败或中断 | 显示逐项结果，未完成自动绑定不生效，重试不重复建号 |
| AC-13 | 同名 AD 对象被删除后重建 | objectGUID 不同导致阻断，不沿用旧授权 |
| AC-14 | 员工尝试替换请求中的账号标识 | 只能操作服务端实时唯一匹配的本人 AD 对象 |
| AC-15 | 员工会话过期、重放、配置或匹配目标变更 | 拒绝密码重置，要求重新验证 |
| AC-16 | 密码重置成功 | 密码生效，会话消费；日志和数据库无明文密码 |
| AC-17 | 无 LDAPS 匹配、受保护或禁用账号 | 阻断重置；无本地绑定但唯一匹配时允许重置 |
| AC-18 | 手动和定时任务同时触发 | 写入串行执行，不产生重复并发同步 |
| AC-19 | 同步期间员工重置密码 | 员工页面仍可访问；同步不覆盖员工密码 |
| AC-21 | 员工从未同步且无本地绑定 | 钉钉身份在 LDAPS 中唯一匹配时，可确认重置本人密码 |
| AC-20 | 备份恢复 | 配置和绑定可恢复，恢复后核验 AD；不得把恢复本地数据视作 AD 回滚 |

性能验收使用企业实际人数与部门规模的数据集，记录全量耗时、单人耗时和员工页面响应；基线未测量前不承诺固定吞吐量。错误提示必须包含可定位原因，不能仅显示“失败”。

## 12. 显式简化与行为差异汇总

| 现有平台能力 | 新系统处理 |
| --- | --- |
| 多组织、多连接器 | 单一配置及目录身份锚点 |
| 多种命名策略及碰撞兜底 | 三种基础命名选择，冲突转人工 |
| 多层匹配与身份治理 | 一套匹配配置及一张有效绑定关系 |
| OU 放置兜底策略 | 明确主部门或人工指定 |
| 配置发布、独立审批中心 | 任务内预览、版本校验和高风险确认 |
| 自动绑定提交语义 | 预览不绑定；逐人操作成功后提交，不等待整批成功 |
| 绑定清扫工作流 | 页面核验与显式解绑，不自动清扫 |
| 快照与数据质量中心 | 当前采集完整性检查及人员行内错误 |
| 多套后台和部署入口 | Django Web 与一套宿主部署流程 |
