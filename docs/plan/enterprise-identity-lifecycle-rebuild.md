# 企业身份全生命周期重构实施基线

## 1. 目标与实施原则

本次重构把 AD Org Sync 从“源账号直接映射 AD 用户名”的同步工具升级为以企业身份为核心的身份治理与安全执行系统。所有新增能力必须满足：

1. 使用真实 Provider、持久化模型和现有 Dry Run / Apply 执行链，不以静态页面或内存模拟代替。
2. 在任何身份歧义、跨组织、跨连接器、稳定标识冲突或权限不确定场景中失败关闭。
3. 先形成不可变快照和可解释预览，再由独立审核/执行角色批准高风险操作。
4. 保持旧 `/jobs`、`/execution-center/*` 和既有绑定数据可迁移、可回滚、可审计。

## 2. 现状审计

### 2.1 可复用能力

- `providers/source` 已提供企业微信、钉钉、飞书 Provider 契约和真实客户端适配器。
- `source_directory_snapshots`、部门/用户快照和字段目录已支持不可变源目录采集、范围选择和指纹。
- `providers/target/ad_ldaps.py` 与 `ADSyncLDAPS` 已提供 AD 读取、OU、用户、组、启停和密码操作的真实 LDAPS 适配层。
- 现有运行时已具备 Dry Run / Apply、计划操作、冲突队列、审核、配置/快照指纹失效、高风险确认、执行日志和组织隔离。
- 现有任务模型支持队列、阶段、租约、恢复提示、部分失败记录和重放请求；现有执行函数采用 ensure/upsert 与成功项落库，可作为幂等执行底座。
- 数据质量中心、生命周期队列、例外规则、配置发布、审计日志和外部通知 outbox 可直接扩展。
- 管理端已经有配置向导、数据源、身份匹配、OU 路由、执行中心和审计入口，并保留兼容路由。

### 2.2 缺失或不足的数据模型

- 缺少独立的 `enterprise_identities`；当前 `user_identity_bindings` 仍把一个源平台账号直接绑定到一个 AD 用户名。
- 缺少独立、不可变的平台账号实体，无法安全地把钉钉、企业微信、飞书账号归并到同一自然人。
- 缺少保存 `objectGUID`、`objectSid`、DN、账号状态、完整 AD 属性和组关系的 AD 账号快照。
- 缺少带来源、证据、创建人、可信度、用途和有效期的统一身份到账户关联模型。
- 缺少可配置且有顺序的身份匹配规则、规范化参数、自动关联阈值、冲突停止策略和规则版本。
- 缺少匹配运行、候选、逐字段证据、人工决策以及永久/仅本次/否定关系模型。
- 缺少多平台字段权威优先级、字段所有权、同步方向和循环更新抑制元数据。
- 现有 OU 映射仅有稳定部门 ID、目标 OU 和继承模式，尚缺根映射、名称转换、排除、虚线部门、缺失 OU 创建、禁用 OU 和移动策略。
- 缺少已有账号接管的导入批次、逐行校验、覆盖预览和审批记录。

### 2.3 缺失或不足的接口

- 平台连接状态尚未完整暴露凭据有效期、API 权限矩阵、授权范围和全部质量计数。
- AD 连接测试尚未形成网络、认证、读用户、读 OU、创建、更新、移动、禁用、密码和证书的逐项能力报告。
- 缺少 AD 目录快照刷新/查询接口和基于稳定标识的候选搜索接口。
- 缺少统一身份创建/合并/拆分、平台账号归并、AD 主/辅助账号用途和证据查询接口。
- 缺少匹配规则 CRUD、匹配运行、候选决策、批量审核和规则版本失效接口。
- 缺少双树 OU 映射预览、部门结构变更分析和字段来源冲突接口。
- 现有 CSV 绑定导入是直接绑定入口，缺少“校验 -> 预览 -> 审批 -> 写入永久关联”的接管批次。
- 缺少针对单个计划操作的安全重试、执行前快照和可回滚字段恢复接口。

### 2.4 页面调整

- 首次进入已经具备步骤向导，可直接扩展为“企业/范围 -> 平台 -> AD -> 数据检查 -> 身份规则 -> OU -> 预览 -> 审核 -> Apply -> 运营”的十步主线。
- 连接器页需改为企业微信、钉钉、飞书和 AD 状态卡，并展示权限/凭据/范围/数量/质量状态。
- 身份匹配页需从“候选用户名”升级为企业身份、多个平台账号、AD 候选、逐字段证据和四级结论工作台。
- OU 路由页需升级为源组织树与 AD OU 树并排映射及结构变更预览。
- Dry Run 需统一展示关联、创建、更新、移动、启停、无变更、排除、冲突、缺失、权限不足和阻断状态。
- 冲突页需提供永久关联、仅本次、创建新账号、关联已有账号、否定、暂缓和排除动作。
- 执行中心需在现有审核门禁上补充执行前快照、可/不可回滚提示、逐项重试和审批人与执行人分离。

## 3. 数据迁移方案

1. 采用只新增的 schema migration，不改写已发布的 1～33 号迁移。
2. 新增企业身份、平台账号、AD 账号、身份关联、匹配规则/运行/候选/决策、字段所有权、AD 快照和接管批次表。
3. 初始化时把每条现有有效 `user_identity_bindings` 回填为一个企业身份、一个平台账号、一个 AD 账号和两条可追溯关联；`target_object_guid` 为空时标记为待 AD 快照校验，绝不以用户名冒充稳定标识。
4. 过渡期保留 `user_identity_bindings` 作为兼容投影；新的永久决策先写统一模型，再由同一事务更新兼容投影。
5. Dry Run 指纹加入规则版本、字段所有权版本、OU 映射版本和 AD 快照指纹；任一配置或快照改变即使旧计划失效。
6. 迁移前继续使用现有自动备份和完整性检查；迁移只允许向前，回滚应用版本时保留新表且旧版本忽略它们。

## 4. 权限与安全风险

- 将现有三角色扩展为系统管理员、连接器管理员、AD 管理员、映射审核人、同步执行人和只读审计员，并保持旧角色的兼容映射。
- 平台密钥、AD 服务账号和导入文件可能包含敏感信息；继续加密密文、禁止日志输出原值、导入原文件设置保留期。
- 邮箱、手机号、姓名和拼音不得成为无条件自动关联依据；只有双侧唯一的强标识或未冲突的永久关联允许自动关联。
- 所有查询和唯一索引必须包含 `org_id`、Provider、连接器或目录范围，防止跨租户/跨域绑定。
- AD 写权限探测必须使用安全、可清理的探测对象或显式配置的只读声明，不能在普通连接测试中修改真实员工账号。
- 服务、共享和测试账号默认排除自动人员匹配和缺失人员禁用。
- 高风险禁用、OU 移动、组移除、覆盖绑定、批量导入和回滚必须记录预览指纹、审核人、执行人、前后值和结果。

## 5. 自动化测试计划

除现有迁移、组织隔离、Dry Run、审核和 Apply 测试外，新增一组端到端领域验收覆盖：

1. 唯一工号自动关联；源或 AD 重复工号时阻断。
2. 同一员工的钉钉和飞书账号归并为同一企业身份；字段冲突进入人工确认。
3. 已占用 AD 账号禁止重新绑定；仅姓名相同不自动关联；唯一邮箱仅建议关联。
4. 人工永久关联优先于自动规则，并保留证据与版本。
5. 新员工创建并进入正确 OU；转岗产生 OU 移动；多部门使用主部门。
6. 离职员工产生延迟禁用预览，服务账号不受影响；返聘不得因同名恢复他人账号。
7. 配置、规则或快照变化使旧 Dry Run 失效。
8. 批量部分失败重试不会重复创建成功账号。
9. 接管导入不会静默覆盖有效绑定。
10. 所有高风险操作具有审批、职责分离和审计证据。

## 6. 实施切片

1. 统一身份 schema、仓储、领域模型、回填迁移和匹配引擎。
2. 平台/AD 快照和质量/权限能力矩阵。
3. 多平台归并、字段权威、匹配运行和人工决策工作流。
4. OU 双树映射、生命周期计划和完整 Dry Run 分类。
5. 接管导入、执行快照、逐项重试、回滚与六角色 RBAC。
6. 管理员页面整合和 18 个端到端验收场景。
