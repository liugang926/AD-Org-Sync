# Django 重构说明

## 范围

首期固定钉钉、一个企业和一个 AD 域。原工作区未提交修改保留在原目录；重构位于独立 Git 工作树和 codex/django-single-org 分支。旧实现保留在 Git 历史，不进入新 Python 包或生产镜像。

## 最新需求：密码重置与同步解耦

员工钉钉授权码由服务端交换为可信 userId，再读取员工详情。按单独配置的工号、邮箱或 userId 精确查 AD，要求唯一、非保护且启用。结果以短期令牌摘要和 objectGUID 保存。员工确认密码时重新读取钉钉与 AD，核对目标 GUID，原子消费令牌再写入密码。

该流程不读 Person、Binding 或 Job；无需同步成功，无需先建立本地绑定。未匹配或歧义只提示联系管理员，不让员工输入任意 AD 用户名。

## 继承与调整

继承：稳定来源 ID、人工绑定优先、唯一匹配、保护账号、受管 OU 边界、局部同步不禁用其他人员、只读预览、过期计划阻断。

调整：按人员成功提交绑定；明确工号匹配；三个基础命名方式；人员行内冲突；Django Admin 仅配置和只读审计；独立 worker 与 SQLite 任务表；不迁移旧数据库。

OU 初次按层级建立，绑定后名称或层级变化需人工确认。不自动删除账号/OU，不自动启用命中禁用的账号。原有群组治理、外部集成、桌面端和多租户框架不保留。

## 验证边界

自动测试使用源与 AD 替身。开发测试环境已验证真实钉钉读取、测试 AD 的加密连接和只读预览；自签证书按要求不校验可信链。钉钉工作台 JSAPI、AD 写入及密码策略仍需使用专门测试员工和测试 OU 验收，不能对普通员工密码做测试。

CI 保留原 job 标识和部署门禁，移除桌面 EXE 打包，增加 Django schema 检查及业务回归。PR 通过后仍需明确合并授权，不能直接推 main。
